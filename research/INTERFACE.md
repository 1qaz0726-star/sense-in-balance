## 1. 拓撲

```
筆電 AI Box（Wi-Fi 熱點 + WebSocket server :8765）
  │
  ├─ 感知層   L1 事件注入（保底）／L2 RF-DETR 離線預跑結果回放
  ├─ 規則引擎 決定「說不說、說什麼、代價多少、多急」
  └─ 廣播
       ├──► 平板 Galaxy Tab S9（中控）   收事件 → 端側 SLM 措辭 → 顯示 + 完整卡片
       └──► 手機 Galaxy S21（車前螢幕）  收事件 → 顯示一句話（由平板廣播回來）
```

**SLM 跑在平板（Tab S9）上。** 手機端不載入模型。

⚠️ **這代表措辭結果要從平板回廣播給手機**，否則兩塊螢幕會不同步。建議平板把 SLM 產出的句子以 `phrase` 事件回廣播（欄位：`event_id` + `text`），手機收到才顯示；在收到之前手機只顯示狀態燈。

🔴 **未驗證**：2026-09-29 的所有端側實測都在 **S21（Snapdragon 888 / Adreno 660）**上做的，
**Tab S9（SM8550 / Adreno 740）從來沒跑過**。`整合計畫_v2` §8 的複合記憶體估算 2.54–2.87 GB，
而 SM-X710 是 8GB 還是 12GB 版**目前未知**。開工前必須先做「驗證一」實機壓測。

⚠️ **網路**：Wi-Fi／筆電熱點，不走 Ethernet（零採購決定的連帶結果）。
連帶好處：沒有啞交換器，不會拿到 `169.254.x.x`，靜態 IP 那個坑消失。

## 2. 事件信封

AI Box → 所有螢幕，JSON，UTF-8，一則一個 WebSocket text frame。

```json
{
  "schema": "1.0",
  "event_id": "evt_000137",
  "ts": 1790000000.123,
  "source": "L1",
  "domain": "cabin_air",
  "state": { },
  "decision": { },
  "availability": "ok"
}
```

| 欄位 | 型別 | 必填 | 說明 |
|---|---|---|---|
| `schema` | string | ✅ | 固定 `"1.0"`。收到不認得的版本就**不要顯示**，改顯示降級狀態 |
| `event_id` | string | ✅ | 單調遞增，`evt_` + 6 位數。重複收到同一個 id 就忽略 |
| `ts` | float | ✅ | Unix 秒，含小數。用來量三屏 skew |
| `source` | enum | ✅ | `L1` 人工注入／`L2` 偵測模型預跑結果 |
| `domain` | enum | ✅ | 見 §3 |
| `state` | object | ✅ | 當下的原始數值，見 §4 |
| `decision` | object | ✅ | 規則引擎的決策，見 §5 |
| `availability` | enum | ✅ | `ok`／`degraded`／`down`，見 §7 |

## 3. `domain`：有哪些事件

10/07 版**只有這三個**，對應影片的四個情境。

| `domain` | 觸發來源 | 出現在哪個情境 |
|---|---|---|
| `cabin_air` | 模擬 CAN 序列（CO₂、溫度、循環） | 情境 A（沉默）、情境 B（主動） |
| `blind_spot` | L1 注入，或 L2 預跑的偵測結果 | 情境 C（安全） |
| `query` | 駕駛在中控輸入問題（停車狀態） | 情境 D（問答） |

⚠️ **`lane_departure`（車道偏離）刻意不做。** 提案文件裡會提到它是法規強制項目，但 10/07 版不實作，不要在 UI 預留它的分支。

## 4. `state`：原始數值

`state` 的欄位**依 `domain` 不同**。螢幕端只讀自己需要的，看到不認得的欄位要忽略而不是報錯。

### `domain = "cabin_air"`

```json
"state": {
  "co2": 1980, "co2_label": "高", "trend": "↑", "trend_label": "上升",
  "t_in": 26, "t_out": 31, "recirc": "內", "occ": 2, "speed": 90
}
```

| 欄位 | 型別 | 說明 |
|---|---|---|
| `co2` | int | ppm |
| `co2_label` | string | `正常`／`偏高`／`高`／`很高` |
| `trend` | string | `↑↑`／`↑`／`→`／`↓` |
| `trend_label` | string | 同上的中文 |
| `t_in` / `t_out` | int | 車內／車外溫度，攝氏 |
| `recirc` | string | `內`／`外` |
| `occ` | int | 乘員數 |
| `speed` | int | km/h |

### `domain = "blind_spot"`

```json
"state": { "side": "right", "object": "機車", "ttc_s": 1.8, "speed": 45,
           "bbox": [0.62, 0.41, 0.19, 0.33], "confidence": 0.87 }
```

| 欄位 | 型別 | 說明 |
|---|---|---|
| `side` | enum | `left`／`right` |
| `object` | string | 中文標籤：`機車`／`自行車`／`行人`／`車輛` |
| `ttc_s` | float\|null | 碰撞時間（秒）。L1 注入時可為 `null` |
| `speed` | int | 本車車速 |
| `bbox` | [float×4]\|null | 正規化 `[x, y, w, h]`，**左上為原點**。`source=L1` 時為 `null` |
| `confidence` | float\|null | 0–1。`source=L1` 時為 `null` |

### `domain = "query"`

```json
"state": { "question": "冷氣濾網多久換一次？", "online": false }
```

| 欄位 | 型別 | 說明 |
|---|---|---|
| `question` | string | 駕駛輸入的原文 |
| `online` | bool | 送出當下 AI Box 有沒有外網。**這個值決定 §6 的回答來源** |

## 5. `decision`：規則引擎的決策 🔴 最重要的一段

```json
"decision": {
  "action": "切換外循環",
  "urgency": "proactive",
  "limit": 15,
  "reason": "CO2 1980 偏高且仍在上升",
  "cost": "車內將升溫約2度"
}
```

| 欄位 | 型別 | 必填 | 說明 |
|---|---|---|---|
| `action` | string | ✅ | 要做的動作。**`urgency = silent` 時固定是 `"維持現狀"`** |
| `urgency` | enum | ✅ | `safety`／`proactive`／`reply`／`silent` |
| `limit` | int | ✅ | 字數上限，由 `urgency` 決定，見下表 |
| `reason` | string | ✅ | 為什麼。可以是空字串 |
| `cost` | string | ✅ | 代價。沒有就是空字串 `""`，**不要用 null** |

### 四級緊急度

| `urgency` | 中文 | `limit` | 手機怎麼呈現 | 平板怎麼呈現 |
|---|---|---|---|---|
| `safety` | 安全 | **8** | 紅底大字，全屏 | 事件記錄一列 |
| `proactive` | 主動告知 | **15** | 單行提示條 | 完整卡片：數值＋原因＋代價 |
| `reply` | 回答 | **30** | 不顯示 | 對話區 |
| `silent` | 不說話 | **0** | 只留狀態燈 | 靜態儀表 |

### 🔴 三條不可違反的約束

這三條是 2026-09-29 手機實測量出來的，不是設計時想的：

1. **`action` 是唯一的事實來源。** SLM 的輸出只能換句話說，**不可以改成別的動作**。
   實測：v1 提示下，決策是「建議稍後換氣」被講成「快換外循環」，**4 題中 3 題出錯**。
2. **`action` 含「稍後」「建議」時，措辭不得出現催促詞**（快／立刻／立即／馬上／趕快）。
3. **不得加入 `state` 與 `decision` 裡沒有的宣稱。** 實測有出現「會影響健康」這種輸入裡完全沒有的說法。

> 加上這三條約束後，決策竄改從 3/4 降到 0/4。詳見 `研究/端側化研究/手機實測_新架構v2_評分_20260929.md`。

### 字數怎麼算

**不算標點。** 理由是唸出來的時間才是真正的約束。
判定用 `蒸餾工具/score_phone.py` 的 `body` 正規化（剝掉 `，。、！？；：「」（）,.!?;:"'()` 與空白）。

### `silent` 的約定

`urgency = "silent"` 時，**AI Box 照樣要發事件**，不是不發。

- 平板：SLM 輸出 `<silent>`，更新儀表數值，不彈卡片
- 手機：畫面只更新狀態燈，**不顯示任何文字**（平板不會回廣播 phrase）

⚠️ 不發事件的話，螢幕分不出「系統判斷不用講」和「系統掛了」——那正是 §7 要解決的問題。

## 6. 平板端 SLM 的輸入輸出

**輸入**：由收到的事件組出下面這段純文字，逐字照這個格式（模型是照這個格式訓的）：

```
狀態: co2=1980↑ 車內=26 車外=31 循環=內 乘員=2 車速=90
決策: 切換外循環 | 原因=CO2 1980 偏高且仍在上升 | 代價=車內將升溫約2度
緊急度: 主動告知 | 上限: 15字
```

- `代價=` 那一段**只在 `cost` 非空時才加**，連同前面的 ` | ` 一起
- 緊急度用中文（`安全`／`主動告知`／`回答`／`不說話`），不是英文 enum

**輸出**：一句話，或 `<silent>`。

### ⚠️ flutter_gemma 的雷（一定要寫在這裡）

```dart
await FlutterGemma.installModel(
  modelType: ModelType.qwen,
  fileType: ModelFileType.task,   // 🔴 必須明寫
).fromFile(path).install();
```

`fileType` 的**預設值是 `ModelFileType.binary`**。`.litertlm` 沒明寫 `task` 就會被多套一層 Qwen chat marker，造成雙重包裹。
（0.12.6 的 `extensions.dart:50`，`task` 分支直接回傳原文，確認過原始碼。）

### `query` 的回答來源

| `state.online` | 回答誰來給 |
|---|---|
| `false` | 本地知識庫檢索直答。查不到就回「這個我查不到，請參考車主手冊」——**不要丟給 SLM 自由發揮，它會編** |
| `true` | 雲端 LLM |

> 🔴 **雲端供應商尚未決定**，決定後補進這裡並升版號。若 10/07 前未實作，揭露表誠實申報 **Offline AI**。

## 7. `availability`：三態指示燈

三塊螢幕都要有一顆狀態燈。**這是法規要求的精神，不是裝飾**——台灣 LDWS 檢測基準有失效偵測試驗，系統失效必須啟動警示；UN R151 須給「不可用」提示。

| 值 | 意思 | 燈號 |
|---|---|---|
| `ok` | 感知與決策都正常 | 綠 |
| `degraded` | 部分功能降級（例：L2 偵測沒跑、離線中） | 黃 |
| `down` | 無法判斷，不要相信畫面 | 紅 |

### 螢幕端的逾時規則

**超過 3 秒沒收到任何事件（含 silent），螢幕自行把狀態燈打成 `down`。**

⚠️ 這條是螢幕自己判斷的，不是等 AI Box 告訴它——AI Box 掛了就不會告訴任何人。

## 8. 心跳

AI Box 每 **1 秒**發一則事件，即使什麼都沒變（那就是 `urgency = silent`）。

這樣做有三個好處：①§7 的逾時判斷才有依據 ②`ts` 可以直接量三屏 skew ③沉默是常態這件事在資料上看得見。

## 9. 版本與相容

- `schema` 只在**不相容**變更時升版（改名、改語意、刪欄位）
- 加可選欄位不升版，但螢幕端**必須忽略不認得的欄位**，不可以報錯
- 螢幕端收到不認得的 `schema` 或 `domain`：**不顯示內容，狀態燈打 `degraded`**

## 10. 給昱羲的最小實作清單

```
□ WebSocket client 連 ws://<筆電IP>:8765
□ 解析 §2 信封，忽略不認得的欄位
□ 依 decision.urgency 分四種呈現（§5 表格）
□ 狀態燈三態 + 3 秒逾時自己打 down（§7）
□ event_id 去重
□ schema 不認得就降級，不要 crash
□ 🔴 載入 .litertlm（注意 §6 的 fileType 雷），跑 SLM 措辭
□ 🔴 把措辭結果回廣播給手機（phrase 事件）
□ 🔴 先做驗證一：Tab S9 實機壓測（載入時間／TTFT／複合 RSS 30 分鐘不被殺）
```

**平板要載入模型並處理 §6**；手機端不載入模型，只顯示平板回廣播的句子。

## 附錄 A：2026-10-05 實作後的變更（相容，schema 仍為 1.0）

5. **§7 狀態燈**：儀表上正常時不顯示，降級／失效才亮；3 秒逾時規則不變。
6. **安全級（盲點）措辭由規則直出，不經 SLM**；`blind_spot` 情境為「先打該側方向燈，1 秒後偵測到」。
