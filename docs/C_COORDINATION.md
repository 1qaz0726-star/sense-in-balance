# C 版本操作與實作說明

這版延續「該說才說」，讓系統核對本車能力，並在優先事件中保存需求。它使用兩份虛構座艙設定，不接真車或自動駕駛。修改前的 Hybrid V3 基準仍在 `codex/hybrid-v3-integration`，舊目錄與模型也保留。

## 如何看這個 Demo

雙擊 `tools/desktop/start-cabin-c.cmd`。電腦本地 V3 服務使用原有模型；平板模擬器是詳細需求端，手機是駕駛摘要端。C 是獨立 `com.auohack.cockpit_hmi.coordination` 套件。

與 Hybrid 基準共用模擬器及通訊埠；啟動器切換模式時只暫停兩個核對過身分的 AVD 上另一個獨立示範 App，不卸載或清除它的資料。App 內尚未完成的記憶體任務不跨重啟保留，請先結束展示。其他正式 App、實機和模型不會被清除。

主展示建議先把 B 配好，A 以本輪實測畫面短對照，避免把現場時間花在設定與配對。兩份設定的相同語句：

> 後座風小一點，音樂也小一點，導航提示不要變。

A 可處理三項候選，確認後模擬值為 2／4／5。B 沒有獨立後座風量介面，仍保留三項需求，整批確認被擋住。風量未知顯示「—」，不偽造 0 或已關閉。

B 流程：先由已配對駕駛授權修補，操作員在「展示情境」選「接管提醒（模擬）」。手機轉到原儀表，固定文字帶說明需求保留。乘客在有效授權內帶入「風量先不用改，其餘照剛剛。」並送出，或明確選取消該項；其餘保留。回到人工駕駛模式後，手機只提示可看摘要，由人點開並一次確認最新版。兩屏收到 Mock 執行回報後才完成，最終後風未動、音樂 4、導航 5。

「帶入」按鈕只填文字，解析仍經真模型。明確點選的取消是人工候選修改，不能把那一路說成模型理解。新修補授權與最終確認都不能在注意力 blocker 中發出；先前有效的修補授權不因警示自動延長。

## 如何切 A/B

一次只使用一份能力設定。先結束或取消待辦，再在「展示情境」模擬停車，等儀表為 P，選擇 A 或 B。必須在來源新鮮且任務 idle/completed/cancelled 時切換；解析、活動候選、失敗、執行中或結果未知都不能切。

成功切換產生新座艙工作階段、撤銷駕駛與乘客授權、清空舊任務並重設模擬值，需要重新配對。無法用切換車型繞過未知執行結果。

## 模型與固定規則的界線

模型沿用 Qwen2.5-1.5B V3，本次不重訓、不改三欄位提示契約。SLM 只輸出原意與局部修正。能力、是否應請駕駛處理、修補權限、數值與執行由程式核對。

`keep` 仍會進批次與回報，值不變；不能說完全沒送該項。`remove` 只取消待辦，不撤回已執行動作。B 必須先明確移除不支援項目，沒有自動部分執行。

來源只有本機明示模擬的 driving-context 與 cockpit-safety。不是 DMS，也不是對道路安全的判定。輔助駕駛模式仍須駕駛監督，接管提醒沒有轉向、煞車或自駕控制。

## 建置與實體部署

沿用已安裝 Flutter 3.35.2、JDK17、Android SDK 與本地模型 runtime。一般操作用已建好的 APK；重建用：

```powershell
.\tools\desktop\build-cabin-c.ps1 -Mode PC
.\tools\desktop\build-cabin-c.ps1 -Mode Native
.\tools\desktop\build-cabin-c.ps1 -Mode Driver -DeviceUrl ws://<S9區網IP>:8767/repair
```

PC 為 x64 模擬器；Native 與 Driver 為 arm64/x64。`10.0.2.2` 僅供模擬器。真手機要以 S9 的正確 LAN 位址重建。普通 S9 平板 App 沒有因此取得真車 CarService/VHAL 權限。

首次原生版在模型設定匯入前輪交付的 V3 manifest 與 `.litertlm`，原版模型另槽可選回。保守預留 8–10GB 給匯入與快取，不是測得最低值。PC 備援服務目前只綁電腦 loopback，實機備援需另外設定區網連線。

## 驗證及限制

2026-10-17 本輪：原 161 項加新增 54 項，共 215/215 測試通過，靜態分析無問題。獨立真模型控制器流程 33 項檢查通過；電腦雙屏另實際操作 A 完成、停車後 B 新工作階段、受限項目、警示中局部修正、解除後明確續辦及逐項模擬回報。雙屏三筆模型解析在畫面顯示約 8.1／4.6／2.5 秒，僅為少量展示，不是速度基準或準確率。

Android 14 x86 模擬器原生 C 版首次 GPU 轉 CPU 暖機失敗，正常重開一次後載入成功；一次真 UI 需求在 CPU 解析為三項正確候選，記錄 33.75 秒且 guard 無改寫。接管與解除後保留同一需求並等待續辦；未做原生版完整 A/B 雙屏執行，也未接 S9。首啟穩定性仍須處理，不能用重試成功宣稱乾淨啟動通過。

本輪展示步驟中的候選與工作階段在 App 記憶體內，關閉後不保留。來源中斷或未知會阻擋新確認；既有候選不會因此自動執行。要重新展示請從新候選開始。啟動器只核對模型與通訊就緒，不能代替完整驗收。

最終可重現測試、真模型原始輸出、實際雙屏畫面、安裝包雜湊與本機提交，以本輪 `output/cabin-c-20261017/` 的驗收收據為準。單元測試使用確定性 fixture，真 V3 解析另記，不把兩者混為模型準確率。

S9 尚未連接、雲端與 ASR 本輪未配置實測、沒有真車或受試者。V3 歷史 D02 音樂誤拒仍存在。普通工程通過與少數已見示範不等於人因成效、離線整機斷網驗證或全面超過原模型。

未來接授權 AAOS/CDC adapter、能力與數值範圍、外部狀態重驗及使用者研究，才有真車與商業 PoC 的依據。簡報的來源資料與比賽對應另隨本輪交付，不以平台已有功能冒稱首創。
